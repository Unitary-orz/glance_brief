# Agents Report Prompt v2

> 这是 agents-report 的格式契约。运行时应直接读取预取 JSON，不重复调用工具、脚本或网络。

## 任务

基于脚本预取的真实 JSON，生成一条中文 AI / Agents 生态报告。只输出最终 Markdown，不输出执行过程。

## 数据来源

- `aihot.categories.industry` 和 `aihot.categories.paper`：近 24 小时 AI HOT v1 数据，用于 AI 生态动态。
- `codexradar.markdown`：脚本已经渲染好的 CodexRadar 板块，必须原样插入。
- `agents_radar.stdout`：脚本按正文标记选取的 ai-trending 内容，用于开源趋势和项目。

不要根据固定 block 编号猜测内容。某个来源失败或为空时，只影响对应板块；不得用常识或其他来源编造补齐。

## 全局约束

- 只写脚本输出中有证据的事实。
- 禁止输出执行过程、工具调用或调试日志。
- 禁止出现 `#` 开头的编号、PR 编号或 Issue 编号。
- 每个趋势或项目要点独占一行，以 `- ` 开头。
- 项目分类标题是普通文本独立行，不加列表符号。
- 板块之间使用 `---`，不使用装饰性长横线。
- 不要复用示例中的项目名、数字或结论；示例只说明版式。
- 不要调用发送工具；Cron 负责投递。

## 固定输出结构

```markdown
📡 **agents-radar 生态报告 | [日期]**

**🤖 AI 生态动态**

- ① [动态概括]：简洁描述（来源：[来源A](url) · [来源B](url)）
- ② [动态概括]：简洁描述（来源：[来源A](url) · [来源B](url)）
- ③ [动态概括]：简洁描述（来源：[来源A](url) · [来源B](url)）

---

【第二个板块｜必须原样插入】

[原样插入 `codexradar.markdown`；该字段自身已经包含 `**🧠 CodexRadar 智力效率**` 标题，不要在前面重复添加标题，也不要改写其中的模型名、数字、括号、分隔符或排序。]

---

**🔥 开源热点趋势**

- ① [总体趋势综述]
- ② [总体趋势综述]

[普通文本分类标题]
- 热门项目：...
- 其他项目：...
```

## AI 生态动态规则

- 综合 `industry` 和 `paper` 的真实条目，生成约 3 条动态。
- 优先关注智能体、编排、技能、工具链、安全和相关研究；如果原始内容是其他 AI 资讯，只按原文概括。
- 每条动态正文不超过 140 字，写作目标约 120 字。
- 来源链接使用 `items[*].links.aihot`；来源名使用 `items[*].source.name`。
- 每行动态末尾追加 2～3 个短来源链接，优先使用 `links.aihot`；链接文本控制在 2～8 个字，超过时缩写；不要把完整新闻标题做成链接。
- 来源链接统一放在动态行末，不拆行。

## CodexRadar 规则

- 完整插入 `codexradar.markdown`。
- 不重新计算、不改数字、不改模型名、不改榜单顺序。
- 数据不可用时，原样保留脚本生成的“信息有限”提示。

## 开源热点趋势规则

- 前两行只根据“今日速览”“趋势信号分析”“社区关注热点”等真实正文归纳总体趋势、技术方向或生态变化。
- 前两行不得出现具体项目名、仓库名、公司名、团队名、模型名、Star 数或单个项目简介。
- 具体项目只能出现在后面的分类明细中。
- 分类标题为普通文本独立行。
- 每个分类只输出两行：`热门项目` 和 `其他项目`。
- `热门项目` 选择原文 `+X today` 最高的一个；没有星数时按原文顺序选择第一项。
- 其余项目合并为一行；没有剩余项目时写 `其他项目：无`。
